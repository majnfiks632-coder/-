# Оболочка ядра ДубинаОС (этап 8)

## Зачем

После того как этап 4 даёт нам PS/2 клавиатуру и журнал, естественный
следующий шаг — простой интерактивный командный интерпретатор прямо в ядре.
Оболочка нужна для:

* интерактивной отладки ядра без загрузки полноценного userspace;
* запуска самопроверок «по запросу» (память, потоки, время);
* проверки, что ввод-вывод полностью работает (PS/2 → ядро → VGA + UART);
* плацдарма для будущих этапов (доступ к ДубФС, запуск программ на «Дубине»).

Это **не** замена полноценной оболочке userspace — после этапа 11 появится
отдельная пользовательская «КомандЪ», и эта ядерная оболочка переедет
в роль аварийного режима (как `init=/bin/sh` в Linux).

## Архитектура

```
┌─────────────────────────────┐
│  главный_цикл (hlt-loop)    │
│   ↓ каждое прерывание       │
│  отладка::окно::обновить()  │  ← при F12 захватывает ввод
│  оболочка::обновить()       │  ← иначе обрабатывает ввод
│   ↓                         │
│  драйверы::клавиатура       │  ← очередь Клавиш из IRQ1
│   ↓                         │
│  print!/println! → VGA+UART │
└─────────────────────────────┘
```

**Принципы**:

* Оболочка молчит, пока открыто отладочное окно (`отладка::окно::активно()`).
* Никаких аллокаций кучи — фиксированный буфер `[u8; 256]` в состоянии.
* Буфер защищён `spin::Mutex`, как и весь ввод-вывод ядра.
* Команды разбираются простым `match` по первой «лексеме» (всё до пробела).

## Реализация

См. `ядро/src/оболочка.rs`. Ключевые функции:

| Функция | Что делает |
|---|---|
| `обновить()` | Опросная процедура из `главный_цикл`. Вычитывает все накопившиеся клавиши и обрабатывает их. При первом вызове печатает приветствие и приглашение. |
| `обработать_клавишу` | Реакция на одну клавишу: символ → echo + добавить в буфер, Возврат → backspace, Ввод → выполнить команду. |
| `выполнить` | Парсер: режет на `(команда, аргументы)`, диспатчит в `команда_*`. |

## Встроенные команды

| Английское имя | Русский синоним | Что делает |
|---|---|---|
| `help`, `?` | `справка` | Список команд |
| `version` | `версия` | Версия ядра, лицензия, архитектура |
| `echo <текст>` | `эхо` | Печатает аргументы |
| `clear`, `cls` | `очистить` | Очищает VGA-экран |
| `mem` | `память` | Физическая память + куча ядра |
| `threads` | `потоки` | Количество и текущий ID потока |
| `uptime`, `time` | `время` | Тики PIT и миллисекунды |
| `panic <текст>` | `паника` | Намеренный panic — для теста паник-обработчика |
| `reboot` | `перезагрузка` | Перезагрузка через PS/2-контроллер (порт 0x64, байт 0xFE) |

## Ввод

Текущий драйвер клавиатуры — US-QWERTY, без поддержки национальных раскладок,
поэтому **командные имена приходится набирать латиницей** (даже если печатает
оболочка по-русски). Русские синонимы оставлены в коде на будущее — когда
этапы 9–14 добавят русскую раскладку, они автоматически станут доступны.

## Почему всё это в одном модуле

Оболочка маленькая (≈250 строк), и пока в ней нет смысла дробить её на
подмодули. По мере роста (история команд, автодополнение, скрипты) разнесём
по файлам.

## Что **не** входит в этап 8 (намеренно)

* История команд (стрелки ↑ / ↓) — этап 14.
* Автодополнение по Tab — этап 14.
* Доступ к ДубФС из оболочки (`ls`, `cat`) — отдельный этап после того, как
  драйвер диска подключит ДубФС в ядро.
* Запуск программ на «Дубине» — этап 11.
* Цветной вывод и статус-строка — этап 14.

## Как проверить локально

```sh
make запуск          # QEMU с собственным загрузчиком
# дождаться приглашения «дубина>»
# набрать `help`, `version`, `mem`, `uptime`
```

CI делает то же самое автоматически: после того как ядро поднялось,
через `qemu-monitor sendkey` вводятся `help`, `version`, `mem` и
проверяется их вывод по `grep` на serial-логе.
