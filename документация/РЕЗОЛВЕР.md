# Резолвер имён языка «Дубина» (этап 6.1)

Это первый шаг реализации этапа 6 «Язык Дубина — компилятор» из дорожной
карты. После лексера и парсера компилятор получает абстрактное
синтаксическое дерево (`аст::Программа`), и теперь резолвер привязывает
каждое употребление идентификатора к его объявлению.

## Что делает резолвер

1. Регистрирует все верхнеуровневые объявления (свободные функции,
   классы) в *модульной области* — это даёт нам **forward references**:
   функция `а()` может вызывать функцию `б()`, которая объявлена ниже.
2. Проходит каждое тело функции/метода и для каждого встретившегося
   идентификатора-выражения (`Выражение::Идентификатор`) определяет
   его привязку:
   - параметр текущей функции;
   - локальная переменная этой функции;
   - функция верхнего уровня (по индексу в `программа.объявления`);
   - класс верхнего уровня.
3. Сообщает ошибки:
   - повторное верхнеуровневое имя (`повторное объявление имени «X»`);
   - повторный параметр функции (`повторный параметр «X»`);
   - использование неизвестного имени (`неизвестное имя «X»`).

Результат — `КартаПривязок`, которая для каждого исходного `Положение`
идентификатора отдаёт `Привязка`. Эта таблица — вход для следующих
этапов компиляции (проверка типов, кодоген).

## Что *не* делает резолвер сейчас

- **Доступ к членам через `.`**: правый операнд `ДоступКЧлену { имя }`
  не резолвится — для этого нужен тип цели, который появится в проверке
  типов. Лево-операнд резолвится как обычно.
- **Аннотации типов параметров** (`Тип имя`) — типы пока сырые строки,
  без проверки существования.
- **Ссылки между методами одного класса** — нужен implicit `это`/`self`,
  это часть проверки типов.
- **Менеджер модулей** — `использовать стандарт.вывод` сейчас тихо
  игнорируется. Появится вместе с менеджером пакетов «Стремянка».

Все эти места помечены `// TODO(этап-6.2): ...` в коде.

## Семантика присваивания (важно!)

В языке «Дубина» парсер *пока не разбирает* ключевое слово `пусть`/`var`.
Поэтому единственный способ создать новую локальную переменную в функции
— присвоить значение имени, которое ещё нигде не видно (в стиле
Python/Lua):

```
main()(р):
    х = 1            # создаём локальную «х»
    х = х + 1        # присваиваем существующей «х»
    р = х
;
```

Когда парсер начнёт разбирать `пусть`, эта эвристика будет заменена на
явную: первое присваивание само по себе перестанет создавать локальную,
а будет нужен `пусть х = 1`.

## Структуры данных

```rust
pub enum ПутьФункции {
    Свободная(usize),                    // индекс в программа.объявления
    Метод { класс: usize, метод: usize } // (класс_idx, метод_idx)
}

pub enum Привязка {
    Параметр { функция: ПутьФункции, индекс: u32 },
    Локальная { функция: ПутьФункции, индекс: u32 },
    Функция(usize),  // индекс свободной функции в программа.объявления
    Класс(usize),    // индекс класса в программа.объявления
}

pub struct КартаПривязок {
    идентификаторы: HashMap<Положение, Привязка>,
    функции: HashMap<String, usize>,
    классы:  HashMap<String, usize>,
}
```

Ключ привязки — `Положение { строка, столбец }`. Парсер гарантирует, что
ни одна другая лексема не начинается в той же точке исходника, поэтому
`Положение` уникально идентифицирует идентификатор.

## CLI

```
дубина проанализировать файл.дуб
```

Печатает либо `OK: имена резолвятся.` со счётчиками, либо построчные
сообщения об ошибках (с координатами).

## Тесты

Юнит-тесты находятся в самом файле `язык_дубина/компилятор/src/резолвер.rs`,
запускаются обычной командой:

```
cargo test -p dubina-compiler
```

Покрывают:
- пустую программу,
- регистрацию верхнеуровневой функции и класса,
- резолв параметра,
- создание локальной первым присваиванием,
- вызов другой свободной функции,
- рекурсивный вызов,
- forward references,
- ошибку неизвестного имени,
- ошибку повторной функции верхнего уровня,
- ошибку повторного параметра,
- видимость локальной только в её функции.
