# Проверка типов языка «Дубина» (этап 6.2)

После [резолвера имён](РЕЗОЛВЕР.md) компилятор переходит к **типизации**:
проходит каждое выражение, выводит/проверяет его тип и сообщает
несовместимости.

## Базовые типы

| Тип | Имена в коде | Литералы | Пример |
|---|---|---|---|
| `Цел` | `Цел`, `Целое`, `Число` | `42` | целое произвольной ширины |
| `Дес` | `Дес`, `Десятичное` | `1.5`, `1/2` | десятичное |
| `Стр` | `Стр`, `Строка` | `"эй"` | UTF-8 строка |
| `Лог` | `Лог`, `Логическое` | `да`, `нет` | логическое |
| `Пусто` | `Пусто` | `пусто` | единичный |

Имя типа, не входящее в эту таблицу (например, имя пользовательского
класса), пока трактуется как `Неизвестный` — операции с ним проходят
молча. Полноценная проверка пользовательских типов появится вместе с
этапом 6.3 (типы объектов).

## Что проверяется

- арифметика `+ - * / % степень` — операнды должны быть числовыми;
  `Цел + Дес → Дес`;
- сравнения `== != < > <= >=` — операнды совместимых типов; результат `Лог`;
- логические `и`, `или`, унарный `не` — требуют `Лог`, возвращают `Лог`;
- условие `Если`, `Пока` обязано быть `Лог`;
- диапазон `Цикл по …` — числовой;
- вызов функции:
  - количество аргументов должно совпадать с параметрами;
  - тип каждого аргумента должен совпадать с объявленным типом
    параметра (если он есть);
- присваивание локальной — первое присваивание фиксирует тип, последующие
  должны соответствовать;
- присваивание параметру — должно соответствовать его объявленному типу.

## Что *пока* не проверяется

- типы возвращаемых значений (нужна привязка возвратных параметров —
  этап 6.3);
- доступ к членам объектов (`a.b`) — нужны полноценные типы классов;
- вывод типов в стиле Хиндли–Милнера — сейчас простой однопроходный.

Все эти места помечены `// TODO(этап-6.3): ...` в коде.

## CLI

```
дубина типизировать <файл.дуб>
```

Печатает либо `OK: типы согласованы.`, либо построчные сообщения вида:

```
Ошибка типизации: [2:14] арифметика требует числовой левый операнд, а получили Стр
```

## Внутреннее устройство

Тип-чекер (`типизация::Типизатор`) строит таблицу
`ПутьФункции → (индекс_локальной → Тип)` по мере прохода тел функций.
Первое присваивание локальной фиксирует её тип; повторные сверяются с
ним. Это покрывает практический сценарий, когда переменная вводится
первым присваиванием (как в Python), не требуя пока ключевого слова
`пусть`.

Параметры функций берутся из их объявлений; если у параметра указан
тип (`Цел а`), то аргумент при вызове проверяется на совпадение с этим
типом. Если тип не указан (`а`), параметр имеет тип `Неизвестный` и
любой аргумент допустим — это позволяет писать «дженерик»-подобный
код в первой версии без формального вывода типов.

Тип результата вызова функции — это тип единственного объявленного
возврата. Если у функции нет возвратов — `Пусто`. Если возвратов
больше одного — `Неизвестный` (множественный возврат пока не
поддерживается типизатором).
