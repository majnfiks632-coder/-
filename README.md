# ДубинаОС

Микроядерная операционная система с упором на безопасность. Полностью на русском языке — от загрузчика до пользовательских приложений.

## Главные идеи

- **Микроядро (в работе)**: задумано так, что в ядре живут только потоки, адресные пространства, IPC и базовые прерывания, а файлы/окна/драйверы — отдельные службы. С v0.1.0+ каркас драйверов и реализации (`таймер-ядра`, `клавиатура-ps2`) физически вынесены в отдельный workspace-crate `службы/драйверы` и подключаются к ядру только как зависимость. ДубФС и оболочка пока ещё внутри ядра; их вынос — следующий этап.
- **Приложения «в банке» (запланировано)**: программа сама по себе может выполнять только вычисления на ЦПУ/ГПУ; любое взаимодействие с внешним миром — только через явно выданные `способности`. Capability-таблица в ядре уже есть; полноценный ring 3 и `int 0x80` появятся на этапе 7.
- **Свой язык программирования «Дубина»**: безопасный по построению. Нет сырых указателей, нет inline asm, нет FFI, нет рефлексии, нет ambient authority. Сейчас компилятор доходит до AST + типизации; кодогенерация — следующий этап.
- **Динамическая разрядность чисел**: тип `Число` физически занимает столько бит, сколько нужно для текущего значения, округлённо до степени двойки. Сейчас реализована арифметика до 64 бит; bigint-расширение запланировано.
- **Архитектуры**: x86_64 (загружается, оболочка живая) и aarch64 (грузится, без оболочки).
- **Свой загрузчик** — Legacy BIOS (MBR + Stage2) и UEFI x86_64 (загружает ядро по ELF, передаёт framebuffer/ACPI/карту памяти через ДубПрото).
- **Своя файловая система ДубФС** с журналированием и контрольными суммами **BLAKE3-256** на каждый блок (4 КиБ). AES-XTS-шифрование тома и copy-on-write — запланированы (см. [`ДОРОЖНАЯ_КАРТА.md`](ДОРОЖНАЯ_КАРТА.md)).
- **Аппаратная безопасность**: ядро использует NX, CR0.WP, SMEP, SMAP и UMIP, если CPU их поддерживает (см. `арх/x86_64/безопасность.rs`).
- **Вытесняющий планировщик** в стиле Windows-NT: 32 уровня приоритета (0–15 динамические, 16–31 реал-time), многоуровневая очередь готовности, round-robin внутри уровня, понижение и +2-буст при пробуждении из IPC, idle-поток, преэмпция через IRQ0 (PIT @ 100 Гц).
- **Тестирование**: всё проверяется в QEMU.

## Быстрый запуск

Нужны пакеты:
- `qemu-system-x86`, `qemu-system-arm` — эмуляция;
- `nasm`, `binutils` (для `objcopy`) — собственный загрузчик;
- `xorriso`, `mtools`, `grub-pc-bin` — только для альтернативного пути через GRUB;
- `dosfstools`, `mtools`, `parted` (или `sgdisk`), `ovmf` — только для UEFI-пути
  (`make запуск-uefi`);
- Rust **stable** с `rust-src`, цели `x86_64-unknown-none`, `aarch64-unknown-none`,
  `x86_64-unknown-uefi` (всё подтянет `rust-toolchain.toml` автоматически).

```bash
# Запуск собственного загрузочного образа (свой MBR + Stage2 + ядро) в QEMU
make запуск

# Запуск через GRUB Multiboot2 ISO (для проверки совместимости)
make запуск-grub

# Сборка и запуск ядра aarch64 в QEMU virt
make запуск-aarch64

# Юнит-тесты компилятора и рантайма
make тесты
```

После загрузки на serial-порт идёт примерно такой вывод:

```
DubinaOS MBR: loading stage2...
MBR: stage2 loaded, jumping...
Stage2: hello, real mode 16bit
Stage2: A20 enabled
Stage2: kernel loaded at 0x10000, switching to PM32...

╔══════════════════════════════════════════════════╗
║              Д У Б И Н А   О С                   ║
║         Версия 0.1.0 — этап «Фундамент»          ║
╚══════════════════════════════════════════════════╝

[OK] Архитектура: x86_64 (long mode)
[OK] Идентификационное отображение 0..4 ГиБ установлено
[OK] GDT с 64-битным сегментом загружен
[ИНФО] Магия загрузчика: 0x00000000D0BA0BE5
[ИНФО] Загружено через собственный загрузчик ДубинаОС (MBR + Stage2)
```

Ровно до банера ядра проходит вся цепочка наших собственных компонентов:
**BIOS → MBR (наш, 512 байт) → Stage2 (наш, ~1 КиБ, real mode → protected mode)
→ ядро (наше, .code32, переходит в long mode и зовёт Rust).** GRUB не используется.

## Запуск на Android через Limbo (QEMU)

Готовый загрузочный образ `сборка/dubina.img` (1 МиБ) — это обычный raw-диск
с MBR, его можно загрузить в [Limbo PC Emulator](https://github.com/limboemu/limbo)
прямо на телефоне. Краткая инструкция:

1. Скопируй файл `dubina.img` на телефон (например, во `Внутреннюю память/Limbo`).
2. Открой Limbo, нажми `New` и создай новую виртуальную машину.
3. Параметры:
   - **Architecture**: `x86_64` (или `x86`, если 64-бит недоступен — наш MBR
     стартует в 16-битном real mode и сам поднимает long mode);
   - **Machine Type**: `pc` (Standard PC, i440FX);
   - **CPU Model**: `qemu64` (или `default`);
   - **CPU Cores**: `1`;
   - **RAM**: `256 MB` (минимум 64 МиБ);
   - **Hard Disk A**: укажи путь к `dubina.img`,
     **Disk Interface**: `ide`, **Boot Device**: `Hard Disk`;
   - **VGA Display**: `std`;
   - **Enable Sound / Network**: можно выключить.
4. Нажми `Start`. Через 1–2 секунды появится наш банер `Д У Б И Н А   О С`,
   потом самопроверки подсистем и приглашение `дубина>`.
5. Команды оболочки (русские и английские синонимы):
   * `справка` / `help` — список команд;
   * `версия` / `version`, `память` / `mem`, `время` / `uptime`;
   * `процессы` / `ps` — таблица потоков ядра;
   * `мониторинг` / `top` — память + потоки в одном окне;
   * `сп` / `ls`, `сд` / `cd`, `тут` / `pwd` — навигация по ДубФС
     (живая ОЗУ-ФС, монтируется при старте на 1 МиБ ОЗУ);
   * `вывести` / `cat ПУТЬ` — напечатать файл; `записать ПУТЬ ТЕКСТ` — записать;
   * `создатькаталог` / `mkdir ПУТЬ`, `создатьфайл` / `touch ПУТЬ`,
     `удалитьфайл` / `rm ПУТЬ` — управление файлами;
   * `статфс` / `df` — статистика ДубФС (свободные блоки и иноды);
   * `задать` / `set ИМЯ ЗНАЧЕНИЕ`, `удалить` / `unset`, `показать` / `env` —
     переменные оболочки;
   * `поиск` / `find ОБРАЗЕЦ`, `сосчитать` / `wc` — фильтры конвейера;
   * `история` / `history` — последние команды;
   * `дерево` / `tree` — рекурсивный список каталога;
   * `голова` / `head [-N] ПУТЬ`, `хвост` / `tail [-N] ПУТЬ` — первые/последние строки;
   * `копировать` / `cp ОТКУДА КУДА`, `переместить` / `mv ОТКУДА КУДА`,
     `дописать` / `append ПУТЬ ТЕКСТ` — операции с файлами;
   * `сис` / `uname [-a]`, `ктоя` / `whoami`, `дата` / `date`,
     `часы` / `clock` — сведения о системе;
   * `сложить` / `calc 2+3*4` — арифметика прямо в оболочке;
   * `лого` / `logo`, `демо` / `demo` — заставка и демонстрация всех подсистем;
   * `редактор` / `edit ПУТЬ` — подсказка по редактированию;
   * `убить` / `kill ИД` — заглушка (полная реализация в этапе 9);
   * `очистить` / `clear`, `эхо` / `echo`, `перезагрузка` / `reboot`,
     `паника` / `panic` — служебные.

   Дополнительно:
   * `↑`/`↓` — листают историю последних 16 команд;
   * `Tab` — автодополнение команды (если совпадение единственное —
     подставляется, если несколько — печатаются варианты);
   * `;` — последовательность команд (`команда1 ; команда2`);
   * `|` — конвейер: `процессы | поиск работник`, `справка | сосчитать`;
   * подстановка переменных: `эхо $ВЕРСИЯ` → `0.1.0`, и так же
     `$АРХ`, `$ПОТОКОВ`, `$ВРЕМЯ` плюс заданные пользователем.

Если используешь UEFI-режим в Limbo — оставь значения по умолчанию (Legacy BIOS),
файл `сборка/dubina.img` это raw-диск с MBR. Для UEFI-пути есть отдельный
образ `сборка/dubina_uefi.img` (GPT + ESP с FAT32, BOOTX64.EFI и yadro.elf),
собирается через `make uefi-образ` / `make запуск-uefi`.

## Запуск на реальном железе

**Современный ПК / ноутбук (UEFI).** Записать `сборка/dubina_uefi.img`
на USB через `dd if=сборка/dubina_uefi.img of=/dev/sdX bs=4M` (или Rufus →
«DD-image» в Windows). В UEFI Boot Menu выбрать USB. Secure Boot — **отключить**
(BOOTX64.EFI не подписан). Что увидите: банер ядра, перечисление PCI/AHCI, GPT,
FAT32, переход в оболочку. Сейчас работают: GOP framebuffer, ACPI 2.0+, AHCI
(чтение SATA), MBR/GPT, FAT32-чтение, PS/2-клавиатура. **НЕ работают** на железе:
USB (нужен EHCI/XHCI), сеть (нужен RTL8111 / Intel e1000e / Realtek Wi-Fi),
звук (HDA), батарея/яркость (ACPI AML), тачпад (Synaptics PS/2-mouse / I²C HID),
рингу 3.

**Legacy BIOS / CSM.** Записать `сборка/dubina.img` через тот же `dd`, в BIOS
включить Legacy / CSM, отключить Secure Boot, грузить с USB.

**ASUS X552EA (AMD E1-2100, Radeon HD 8210, RTL8111 LAN, RTL8723 Wi-Fi/BT,
Synaptics, AMD HDA, EHCI USB).** Поддерживается оба режима — UEFI и Legacy CSM.
В UEFI-режиме сейчас работает то же, что и на любом современном ПК (см. выше).
Дополнительно нужны (этап 11 [дорожной карты](ДОРОЖНАЯ_КАРТА.md)): драйверы
Radeon (помимо GOP), RTL8111/RTL8723, Synaptics, AMD HDA, ACPI battery/sleep,
SD-картридер, EHCI HID/MSC.
